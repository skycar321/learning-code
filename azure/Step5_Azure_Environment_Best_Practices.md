# Azure 환경 설정 및 모범 사례
# 이 파일은 Azure Key Vault 학습 계획의 5단계인 'Azure 환경 설정 및 모범 사례'를 위한
# 개념적인 가이드입니다.
# Azure 환경을 안전하고 효율적으로 구성하고 관리하기 위한 핵심적인 모범 사례들을 다룹니다.

## 개요 (Overview)
클라우드 환경에서는 리소스의 생성, 배포, 관리가 유연하게 이루어지지만, 동시에 보안, 비용, 규정 준수 등의
측면에서 주의가 필요합니다. 이 가이드는 Azure 환경을 설정하고 운영할 때 고려해야 할
주요 모범 사례들을 제시합니다.

## 학습 내용 (Learning Content)

### 1. Azure 리소스 그룹(Resource Groups)을 이용한 구성 관리
*   **목표**: 관련 리소스들을 논리적으로 묶어 관리 효율성을 높입니다.
*   **모범 사례**:
    *   **명확한 명명 규칙**: 리소스 그룹의 목적과 포함된 리소스를 쉽게 식별할 수 있도록 명명 규칙을 적용합니다 (예: `rg-myapp-dev-koreacentral`).
    *   **생명 주기 기반**: 동일한 생명 주기를 가지는 리소스들을 하나의 리소스 그룹에 포함합니다. (예: 특정 애플리케이션의 모든 리소스).
    *   **환경별 분리**: 개발, 테스트, 운영 환경을 별도의 리소스 그룹으로 분리하여 관리합니다.
    *   **RBAC 적용**: 리소스 그룹 수준에서 RBAC를 적용하여 권한 관리를 간소화합니다.

### 2. Azure Policy를 이용한 거버넌스 및 규정 준수 (Governance & Compliance with Azure Policy)
*   **목표**: 조직의 표준과 규정을 준수하도록 Azure 리소스를 강제하고 감사합니다.
*   **모범 사례**:
    *   **정책 정의**: 리소스 생성 시 특정 지역만 허용, 특정 태그 강제, 특정 SKU만 사용 허용 등 정책을 정의합니다.
    *   **이니셔티브**: 여러 정책 정의를 하나의 이니셔티브(정책 세트)로 묶어 할당합니다.
    *   **할당 및 범위**: 정책을 필요한 관리 그룹, 구독, 리소스 그룹에 할당하고, 필요에 따라 예외를 설정합니다.
    *   **정기 감사**: Azure Policy 준수 보고서를 정기적으로 검토하여 규정 준수 상태를 확인합니다.

### 3. 리소스 잠금(Resource Locks) 활용
*   **목표**: 실수로 인한 리소스 삭제나 변경을 방지하여 안정성을 확보합니다.
*   **모범 사례**:
    *   **삭제 잠금 (CanNotDelete)**: 프로덕션 환경의 중요한 리소스 그룹, Key Vault, 스토리지 계정 등에 적용하여 삭제를 방지합니다.
    *   **읽기 전용 잠금 (ReadOnly)**: 리소스의 모든 변경을 방지하고 읽기만 허용하여 불필요한 변경을 막습니다. (예: 중요한 설정 파일이 있는 스토리지 계정).
    *   **신중한 적용**: 잠금은 유용하지만, 필요한 변경 작업을 방해할 수 있으므로 신중하게 적용하고, 변경 시에는 일시적으로 잠금을 해제해야 합니다.

### 4. Azure Active Directory (AAD) 통합 및 역할 기반 접근 제어 (RBAC)
*   **목표**: Azure 리소스에 대한 접근 권한을 최소 권한 원칙(Principle of Least Privilege)에 따라 관리합니다.
*   **모범 사례**:
    *   **중앙 집중식 ID 관리**: 모든 사용자, 그룹, 서비스 주체를 Azure AD에서 관리합니다.
    *   **역할 정의**: Azure 기본 제공 역할(Contributor, Reader, Owner 등) 또는 사용자 지정 역할을 사용하여 필요한 최소한의 권한을 부여합니다.
    *   **그룹 활용**: 개별 사용자 대신 Azure AD 그룹에 역할을 할당하여 권한 관리를 단순화합니다.
    *   **정기 감사**: 누가 어떤 리소스에 어떤 권한을 가지고 있는지 정기적으로 검토하고, 불필요한 권한은 회수합니다.
    *   **조건부 접근**: MFA (Multi-Factor Authentication), 위치 기반 접근 등 조건부 접근 정책을 활용하여 보안을 강화합니다.

### 5. 환경별 구성 관리 (Configuration Management for Different Environments)
*   **목표**: 개발, 테스트, 운영 환경 간의 구성 차이를 효율적으로 관리하고 일관성을 유지합니다.
*   **모범 사례**:
    *   **중앙 집중식 구성**: Azure App Configuration, Key Vault 또는 기타 구성 관리 도구를 사용하여 환경별 설정을 중앙에서 관리합니다.
    *   **매개변수화**: ARM 템플릿, Terraform 등 IaC (Infrastructure as Code) 도구를 사용하여 환경별 매개변수를 통해 리소스를 배포합니다.
    *   **CI/CD 파이프라인**: 환경별 구성 배포를 자동화된 CI/CD 파이프라인에 통합하여 수동 오류를 줄입니다.
    *   **보안 분리**: 환경별로 Key Vault, 리소스 그룹, 네트워크를 철저히 분리하여 한 환경의 문제가 다른 환경에 영향을 미치지 않도록 합니다.

## 추가 고려 사항 (Additional Considerations)

*   **비용 관리**: Azure Cost Management를 사용하여 예산을 설정하고, 리소스 사용량을 모니터링하며, 불필요한 리소스를 정리하여 비용을 최적화합니다.
*   **보안 센터/Microsoft Defender for Cloud**: Azure 환경의 보안 상태를 지속적으로 평가하고 위협을 탐지하며, 권장 사항을 제공받습니다.
*   **백업 및 재해 복구**: 중요한 데이터 및 애플리케이션에 대한 백업 전략과 재해 복구 계획을 수립하고 정기적으로 테스트합니다.

이 모범 사례들은 Azure 환경을 안전하고 효율적으로 운영하기 위한 기본적인 가이드라인입니다.
조직의 특정 요구 사항과 규정 준수 요건에 따라 맞춤형 정책과 절차를 수립하는 것이 중요합니다.
