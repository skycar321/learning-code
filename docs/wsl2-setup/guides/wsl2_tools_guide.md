# WSL2 생산성 도구 완벽 가이드 (Why & How)

이 문서는 `wsl2.md`를 통해 설치한 도구들이 **왜 필요한지**, 그리고 **어떻게 사용하여 생산성을 극대화하는지** 설명하는 상세 매뉴얼입니다.

---

## 1. 셸(Shell) 업그레이드: Bash vs Zsh

### ❓ 왜 Bash 대신 Zsh을 쓰나요?
Linux의 기본 셸인 `bash`는 안정적이지만 사용자 편의 기능이 부족합니다. `zsh`은 다음과 같은 강력한 기능을 제공합니다.
*   **강력한 자동완성**: 파일명뿐만 아니라 명령어 옵션(`git commit --<Tab>`)까지 추천해줍니다.
*   **경로 이동 단축**: `cd /u/l/b`만 입력하고 탭을 치면 `/usr/local/bin`으로 자동 확장됩니다.
*   **플러그인 생태계**: 수천 개의 플러그인(Oh My Zsh)을 통해 기능을 확장할 수 있습니다.

### 🎨 Oh My Zsh & Powerlevel10k
*   **Oh My Zsh**: Zsh 설정을 쉽게 관리해주는 프레임워크입니다.
*   **Powerlevel10k**: 터미널 프롬프트(입력창) 디자인 테마입니다.
    *   **시각적 정보**: 현재 Git 브랜치, 수정된 파일 유무, 명령어 실행 시간, 이전 명령어 성공/실패 여부를 아이콘으로 보여줍니다.
    *   **속도**: 매우 복잡한 정보를 보여주면서도 렉이 걸리지 않도록 최적화되어 있습니다.

## 2. Modern CLI 도구 사용법 (핵심 🚀)

Rust로 작성된 현대적인 CLI 도구들은 기존 유닉스 명령어(`cd`, `ls`, `cat`)를 대체하며 압도적인 성능과 편의성을 제공합니다.

### 📂 1. `zoxide` (스마트한 cd 대체재)
*   **Why?**: 프로젝트 경로가 깊어질수록 `cd ~/Documents/Workspace/Project/src` 치기가 너무 힘듭니다.
*   **How**: `zoxide`는 당신이 자주 방문한 경로를 학습(Learning)합니다.
*   **사용법**:
    *   **이동**: `z learning` (경로의 일부만 입력해도 `~/.../learning-code`로 점프)
    *   **선택 이동**: `zi` (방문했던 목록이 나오고 선택해서 이동)
    *   **주의**: 설치 직후에는 기록이 없으므로, 기존 방식(`cd`)으로 한 번 방문해줘야 학습이 됩니다.

### 🔍 2. `fzf` (Fuzzy Finder - 강력한 검색)
*   **Why?**: "아까 그 긴 도커 명령어 뭐였지?" 하고 위쪽 화살표(⬆️)를 50번 누르는 비효율을 없앱니다.
*   **How**: 흐릿한(Fuzzy) 검색을 지원하여, 철자가 정확하지 않아도 찾아줍니다.
*   **사용법**:
    *   **단축키 `Ctrl + R`**: 터미널 히스토리 검색 모드가 열립니다. 기억나는 단어 몇 개만 치면 과거 명령어를 찾아줍니다.
    *   **파일 검색**: `Ctrl + T` (현재 위치 하위의 파일을 검색해서 커맨드 라인에 입력)

### 🎨 3. `eza` (아름다운 ls)
*   **Why?**: 흑백의 `ls`는 파일인지 폴더인지, 실행 권한이 있는지 한눈에 보기 어렵습니다.
*   **How**: 파일 종류별 아이콘 표시, Git 상태 표시(수정됨, 새 파일 등), 트리 구조 보기를 지원합니다.
*   **사용법 (Alias 설정됨)**:
    *   `ls`: 기본 파일 목록 (아이콘 포함)
    *   `ll`: 상세 목록 (권한, 용량, 날짜, **Git 상태**)
    *   `eza --tree`: 하위 디렉토리 구조를 트리 형태로 시각화

### 📖 4. `bat` (Syntax Highlighting cat)
*   **Why?**: `cat file.py`로 코드를 보면 흑백이라 읽기 힘듭니다.
*   **How**: 코드 문법 강조(Coloring), 줄 번호 표시, Git 변경 사항 표시를 해줍니다.
*   **사용법**:
    *   `cat 파일명`: (Alias 설정됨) 내용을 컬러풀하게 보여줍니다.
    *   `/` 키를 눌러 내용 검색이 가능합니다 (less 처럼 동작).

## 3. Zsh 생산성 기능 활용 (꿀팁)

### 💡 자동 제안 (Auto Suggestions)
명령어를 칠 때 희미한 회색 글씨로 추천이 뜹니다.
*   **상황**: `gi`만 쳤는데 회색으로 `git commit -m "update"`가 보임.
*   **실행**: **오른쪽 화살표 키(→)** 또는 **End 키**를 누르면 전체 명령어가 자동 입력됩니다.

### ⌨️ 탭 완성 (Tab Completion)
명령어를 모를 땐 무조건 **Tab**을 두 번 누르세요.
*   `git ch<Tab>` → `checkout`, `cherry-pick` 등 목록을 보여주고 선택 가능하게 함.
*   `docker r<Tab>` → `run`, `rmi`, `rm` 등 추천.

### ⚡ Git Alias (Oh My Zsh 기본 제공)
긴 Git 명령어를 짧게 줄여줍니다.
*   `gst` = `git status`
*   `gaa` = `git add --all`
*   `gcmsg "메시지"` = `git commit -m "메시지"`
*   `gp` = `git push`
*   `gl` = `git pull`

## 4. 성능 및 통합 원리

### 🧠 .wslconfig (메모리 제한)
*   **이유**: WSL2는 리눅스 커널을 가상화 기술로 돌립니다. 제한을 안 두면 리눅스가 캐싱을 위해 윈도우의 램을 100%까지 가져다 쓸 수 있습니다. 게임이나 크롬이 느려지는 주범입니다.

### 🐳 Docker Desktop 연동
*   **이유**: 리눅스(WSL) 안에 도커 엔진을 직접 깔면, 윈도우에서 GUI 대시보드를 못 씁니다.
*   **통합**: 윈도우에 깔린 Docker Desktop이 WSL2를 "백엔드 엔진"으로 사용하게 설정하면, 윈도우의 편의성(GUI)과 리눅스의 성능을 모두 잡을 수 있습니다.

### 🖥️ VS Code Remote-WSL
*   **이유**: 윈도우에 있는 VS Code가 네트워크(SSH)를 통해 리눅스 파일에 접근하는 방식이 아닙니다. VS Code의 "서버" 부분이 WSL 안에서 실행됩니다.
*   **장점**:
    1.  **속도**: 리눅스 파일 시스템 내부에서 도니까 파일 IO가 엄청 빠릅니다.
    2.  **환경 분리**: 리눅스 전용 확장프로그램(파이썬, C++ 컴파일러 등)을 WSL 안에만 설치하므로 윈도우가 깨끗해집니다.
