## 1. AI는 어떻게 말을 알아들을까? (NLP와 LLM)

### 1.1 컴퓨터가 언어를 이해하는 방식 (NLP)
컴퓨터는 0과 1밖에 모릅니다. "사과"라는 단어를 줘도 컴퓨터는 그저 글자(그림)로만 인식합니다. 그래서 우리는 언어를 **숫자(벡터)**로 바꿔줘야 합니다.

- **과거의 방식 (단어 빈도)**: "사과"라는 단어가 몇 번 나왔니?
  - 문제점: "맛있는 사과"와 "Apple"이 같은 뜻인지 모름.
- **요즘 방식 (임베딩)**: 단어의 **의미**를 지도상의 좌표처럼 숫자로 변환.
  - 예: `왕 - 남자 + 여자 = 여왕` 처럼 의미를 더하고 뺄 수 있게 됨.

### 1.2 LLM (대규모 언어 모델)은 무엇인가?
**LLM(Large Language Model)**은 전 세계의 도서관에 있는 책을 다 읽은 **"엄청나게 똑똑한 앵무새"**와 같습니다.

- **Pre-training (사전 학습)**: 
  - 비유: 초/중/고/대학교를 다니며 일반적인 지식을 배우는 과정.
  - 결과: 말하는 법, 일반 상식, 논리력을 갖춤.
- **Fine-tuning (미세 조정)**: 
  - 비유: 의사나 변호사가 되기 위해 전문 연수를 받는 과정.
  - 결과: 특정 분야(의료, 법률 등)에 특화됨.

### 1.3 Transformer: AI 혁명의 심장
GPT(Generative Pre-trained **Transformer**)의 T가 바로 이것입니다.
이 기술의 핵심은 **"Attention(주목)"** 메커니즘입니다.

- **비유**: 여러분이 이 글을 읽을 때, 모든 단어에 똑같이 집중하지 않죠? 중요한 단어에 **"주목(Attention)"**하며 문맥을 파악합니다.
- AI도 문장에서 "그것(it)"이 무엇을 가리키는지 알기 위해 앞뒤 문맥을 동시에 살피는데, 이 기술 덕분에 지금처럼 똑똑해졌습니다.

## 2. AI에게 우리 회사의 지식을 알려주는 법 (RAG)

### 2.1 LLM의 치명적인 단점: "할루시네이션"
AI는 모르는 것도 자신 있게 지어내는 버릇이 있습니다. 이를 **할루시네이션(환각)**이라고 합니다.
또한, AI는 학습 시점 이후의 최신 뉴스나, 우리 회사의 비공개 문서는 모릅니다.

### 2.2 해결책: RAG (검색 증강 생성)
**RAG(Retrieval-Augmented Generation)**는 AI에게 **"오픈북 시험"**을 보게 하는 기술입니다.

- **기존 방식**: AI야, 기억나는 대로 답해줘. (기억력 의존 → 거짓말 가능성 높음)
- **RAG 방식**: 
  1. 질문과 관련된 문서를 **찾아보고(Retrieval)**
  2. 그 문서를 참고해서 **답변을 생성해(Generation)**

### 2.3 핵심 기술: 벡터 데이터베이스
RAG를 하려면 AI가 텍스트를 빠르게 찾을 수 있어야 합니다. 이때 사용하는 것이 **벡터 데이터베이스**입니다.

- **도서관 사서**와 같습니다.
- 우리가 "재밌는 SF 소설 찾아줘"라고 하면, 제목에 'SF'가 없어도 내용(의미)이 비슷한 책을 찾아줍니다.
- **임베딩(Embedding)**: 텍스트를 의미를 담은 숫자(벡터)로 바꿔서 저장하는 기술.

> **요약**: RAG는 **"검색(Search)"**과 **"생성(ChatGPT)"**을 합친 기술입니다.

## 3. 스스로 일하는 AI 비서 (AI 에이전트)

### 3.1 챗봇 vs 에이전트
- **챗봇**: 묻는 말에 대답만 함. (수동적)
- **에이전트**: 목표를 주면 **스스로 계획을 세우고 도구를 사용**해서 일을 처리함. (능동적)

> **예시 상황**: "배가 고픈데..."
> - **챗봇**: "주변 식당을 검색해보세요." (정보 제공 끝)
> - **에이전트**: "근처 맛집을 검색해보니 A식당 평점이 좋네요. 예약해드릴까요? 배달 앱을 켤까요?" (행동 수행)

### 3.2 에이전트의 구성 요소
1. **두뇌 (LLM)**: 상황을 판단하고 계획을 세움.
2. **손과 발 (Tools)**: 검색하기, 이메일 보내기, 엑셀 켜기 등의 도구.
3. **기억 (Memory)**: 사용자의 취향이나 지난 대화를 기억.

### 3.3 멀티 에이전트: "어벤져스 팀" 만들기
한 명의 천재(GPT-4)보다 여러 명의 전문가 팀이 더 일을 잘할 때가 있습니다.
- **기획자 에이전트**: 사용자 요청을 분석하고 업무 분배.
- **개발자 에이전트**: 코드를 작성.
- **검수자 에이전트**: 코드를 확인하고 에러 수정.

이렇게 여러 에이전트가 협력하는 것을 **멀티 에이전트 시스템**이라고 합니다.

## 4. 모든 도구를 연결하는 표준 규격 (MCP)

### 4.1 AI 연결의 문제점: "충전기 지옥"
과거에는 아이폰, 갤럭시, 노트북 충전기가 다 달랐습니다. AI 개발도 마찬가지였습니다.
- AI가 노션(Notion)을 쓰려면 노션 연결 코드를 짜야 하고,
- 슬랙(Slack)을 쓰려면 슬랙 연결 코드를 또 짜야 했습니다.
- 새로운 AI 모델이 나오면 이 작업을 처음부터 다시 해야 했습니다. (N x M 문제)

### 4.2 해결책: MCP (Model Context Protocol)
**MCP**는 AI계의 **"USB-C 타입"** 표준입니다.

- **USB-C 하나면** 갤럭시, 노트북, 아이패드 다 충전되죠?
- **MCP 하나면** Claude, ChatGPT, Gemini 어떤 AI든 노션, 슬랙, 깃허브와 바로 연결됩니다.

### 4.3 왜 혁명적인가?
1. **개발 속도**: 연결 코드를 일일이 짤 필요가 없습니다. (400줄 코드가 3줄로 감소)
2. **호환성**: 한번 만들어둔 도구(MCP 서버)는 어떤 AI 모델에서도 쓸 수 있습니다.
3. **생태계**: 이미 1,000개 이상의 MCP 도구(서버)가 나와 있어서, 가져다 쓰기만 하면 됩니다.

---

## 5. 마무리: AI의 미래 흐름

1. **단순 질문 답변**에서 → **스스로 도구를 쓰는 에이전트**로 진화 중입니다.
2. **AI 혼자 일하는 것**에서 → **팀(멀티 에이전트)으로 협업**하는 구조로 바뀝니다.
3. **복잡한 연동**은 사라지고 → **MCP 같은 표준 규격**으로 모든 앱이 연결됩니다.

이제 AI는 단순히 "말하는 기계"가 아니라, **"행동하는 서비스"**가 되어가고 있습니다.
