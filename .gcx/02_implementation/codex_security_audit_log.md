# Codex Security Audit Report

**Topic**: Access Log Retention & Integrity (Anti-Tampering)
**Model**: gpt-5.1-codex-max
**Reasoning Effort**: extra_high

## 1. 접속기록 보관의 필요성 (Why store logs?)

**결론: 네, 법적/보안적 의무사항입니다.**

단순히 "서비스마다 알아서 하면 되는 것"이 아닙니다. 특히 **개인정보를 다루는 서비스(PRD 호스트)**라면 다음과 같은 이유로 접속 기록 보관이 **강제**됩니다.

### A. 법적 컴플라이언스 (Compliance)
대한민국 및 글로벌 보안 규정에서는 접속 기록 보관을 의무화하고 있습니다.
- **ISMS-P (국내 정보보호 및 개인정보보호 관리체계)**:
    - "접속 기록은 **최소 1년 이상** (개인정보취급자의 경우 2년) 보관해야 한다."
    - "접속 기록이 위변조되지 않도록 **무결성 검증 조치**를 취해야 한다."
- **개인정보보호법**:
    - 제29조(안전조치의무): 개인정보처리시스템에 접속한 기록을 1년 이상 보관/관리해야 함.
- **PCI-DSS (카드 결제 데이터)**, **GDPR (유럽)** 등 대부분의 표준이 요구함.

### B. 포렌식 및 침해 사고 대응 (Forensics)
- 해킹 사고가 발생했을 때, **"누가, 언제, 어떻게 들어왔는지"** 알 수 있는 유일한 증거가 접속 로그입니다.
- 로그가 없으면 공격 경로를 파악할 수 없고, 재발 방지 대책도 세울 수 없습니다.

## 2. 위변조 방지 (Hashing)가 필요한가? (Why Hash?)

**결론: 네, "무결성 입증"을 위해 필수적입니다.**

### 시나리오: 해커가 침입했다면?
해커가 서버에 침투해서 가장 먼저 하는 일은 **자신의 접속 기록(로그)을 지우거나 조작**하는 것입니다.
만약 단순히 텍스트 파일로만 로그를 남겨뒀다면:
1. 해커: `rm access.log` 또는 특정 라인 삭제.
2. 관리자: 침입 사실조차 모르게 됨.
3. 법적 문제: 사고 발생 시 "로그가 조작되지 않았다"는 것을 법정에서 증명할 수 없음 (증거 능력 상실).

### Hashing의 역할
접속 기록에 대해 **Hash(해시)** 값을 생성하여 보관하면 위변조 여부를 확인할 수 있습니다.
- **Hash Chain**: 로그 라인마다 이전 로그의 해시값을 포함하여 체인처럼 연결. 중간에 하나라도 바뀌면 전체 체인이 깨짐 (블록체인 원리).
- **주기적 해싱**: 하루 단위로 로그 파일의 해시값(SHA-256 등)을 생성하여 **별도의 안전한 저장소(WORM 스토리지 등)**에 보관.

## 3. 구현 방법 (How to implement?)

"그냥 서비스마다 하면 되는 게 아닌가?" -> **개별 서비스가 직접 파일로 관리하는 것은 위험합니다.**

### 권장 아키텍처 (Best Practice)

1.  **로그 중앙화 (Centralized Logging)**:
    - 각 서버(PRD 호스트)에 로그를 남기지 않고, 실시간으로 **별도의 로그 서버(SIEM, ELK 등)**로 전송합니다.
    - 해커가 웹 서버를 장악해도, 이미 전송된 로그 서버의 데이터는 건드릴 수 없습니다.

2.  **WORM 스토리지 (Write Once Read Many)**:
    - 한 번 쓰면 수정/삭제가 불가능한 스토리지(AWS S3 Object Lock 등)에 로그를 저장합니다.

3.  **해시 검증 (HMAC / Hash Chain)**:
    - 로그 파일이 생성될 때 해시값을 계산하여 별도 DB나 블록체인에 저장합니다.
    - 감사(Audit) 시, 현재 로그 파일의 해시를 다시 계산해서 저장된 값과 일치하는지 확인합니다.

### 답변 가이드 (요약)

질문하신 분에게 이렇게 답변하시면 됩니다:

> "단순 권장사항이 아니라, **개인정보보호법 및 ISMS-P 인증 요건**에 따라 접속 기록의 **보관(최소 1년)**과 **무결성 확보(위변조 방지)**는 의무 사항입니다.
>
> 만약 사고가 터졌을 때 로그가 조작되어 있다면 법적 책임을 질 수 있습니다.
> 따라서 각 서버에 텍스트로만 남기는 것보다, **1) 중앙 로그 서버로 실시간 전송**하거나 **2) 로그 파일의 해시(Hash) 값을 주기적으로 생성해 별도 보관**하는 조치가 필요합니다."
