# Azure 모니터링 대시보드 학습 - 1단계: Azure Monitor 기본
# 이 파일은 Azure 모니터링 대시보드 학습 계획의 1단계인 'Azure Monitor 기본'을 위한
# 개념적인 설명입니다. Azure Monitor의 핵심 기능과 아키텍처를 이해하는 데 중점을 둡니다.

## 개요 (Overview)
Azure Monitor는 Azure 및 온프레미스 환경에서 실행되는 애플리케이션, 인프라 및 네트워크의
성능과 가용성을 최대화하는 데 도움이 되는 종합적인 모니터링 솔루션입니다.
다양한 원본에서 데이터를 수집하고, 분석하며, 시각화하고, 경고를 트리거하며, 자동화된
작업을 수행할 수 있도록 지원합니다.

## 학습 목표 (Learning Objectives)
*   Azure Monitor의 기능 및 아키텍처 이해
*   메트릭(Metrics)과 로그(Logs)의 차이점 및 역할 파악
*   Azure 리소스에 대한 기본 모니터링 설정 개념 이해
*   주요 모니터링 데이터 소스 식별

## 학습 내용 (Learning Content)

### 1. Azure Monitor란 무엇인가? (What is Azure Monitor?)
*   **정의**: Azure 환경 전체에서 가시성(Observability)을 제공하는 서비스입니다.
    - 애플리케이션, OS, 네트워크, 인프라 등 모든 계층에서 데이터를 수집합니다.
    - 수집된 데이터를 중앙 집중식으로 분석하고 시각화합니다.
    - 문제 발생 시 즉각적으로 알림을 제공하고 자동화된 조치를 트리거합니다.

*   **주요 기능**:
    - **데이터 수집**: 메트릭, 로그, 추적(Traces) 등 다양한 원본에서 데이터를 수집합니다.
    - **데이터 분석**: 수집된 데이터를 Kusto Query Language (KQL)를 사용하여 쿼리하고 분석합니다.
    - **시각화**: Azure 대시보드, 워크북, Grafana 등 다양한 도구를 통해 데이터를 시각화합니다.
    - **경고**: 특정 조건(임계값 초과, 오류 발생 등) 발생 시 알림을 생성합니다.
    - **자동화**: 경고에 따라 Logic Apps, Azure Functions 등과 연동하여 자동화된 복구 또는 대응 조치를 수행합니다.

*   **아키텍처**:
    - Azure Monitor의 핵심은 데이터를 수집하고 분석하는 두 가지 기본 유형인
      **메트릭(Metrics)**과 **로그(Logs)**입니다.
    - **메트릭**은 시간 경과에 따른 시스템의 특정 측면을 나타내는 숫자 값입니다. (예: CPU 사용률, 네트워크 인/아웃)
    - **로그**는 시스템에서 발생하는 이벤트에 대한 구조화된 텍스트 레코드입니다. (예: 오류 메시지, 웹 요청)

### 2. 메트릭(Metrics) 및 로그(Logs) 이해
*   **메트릭 (Metrics)**
    - **특징**: 숫자 데이터, 가벼움, 실시간에 가까운 응답, 특정 시점의 시스템 상태를 나타냄.
    - **용도**: 성능 트렌드 분석, 실시간 경고, 시스템 가용성 모니터링.
    - **저장**: Azure Monitor 메트릭 데이터베이스에 저장.
    - **예시**: CPU 사용량, 메모리 사용량, 네트워크 트래픽, 디스크 I/O.

*   **로그 (Logs)**
    - **특징**: 비구조화 또는 반구조화된 텍스트 데이터, 다양한 이벤트 정보 포함, 더 많은 컨텍스트 제공.
    - **용도**: 근본 원인 분석, 문제 해결, 감사 및 규정 준수.
    - **저장**: Log Analytics 워크스페이스에 저장되며 Kusto Query Language (KQL)로 쿼리 가능.
    - **예시**: 웹 서버 액세스 로그, 애플리케이션 오류 로그, 시스템 이벤트 로그.

### 3. Azure 리소스에 대한 기본 모니터링 설정
*   **자동 활성화**: 대부분의 Azure 리소스는 생성 시 기본적인 메트릭 수집이 자동으로 활성화됩니다.
*   **진단 설정 (Diagnostic Settings)**:
    - 리소스의 로그 및 추가 메트릭 데이터를 Log Analytics 워크스페이스, Storage Account, Event Hubs 등으로 전송하도록 구성할 수 있습니다.
    - 이를 통해 더 상세한 로깅 및 장기 보관, 분석이 가능해집니다.
*   **활동 로그 (Activity Log)**:
    - Azure 구독에서 발생하는 모든 관리 작업(리소스 생성/삭제, 설정 변경 등)을 기록합니다.
    - 누가, 언제, 무엇을, 어디서 수행했는지 파악하는 데 유용합니다.

### 4. 모니터링 데이터 소스 (Monitoring Data Sources)
Azure Monitor는 다양한 Azure 서비스 및 온프레미스 소스에서 데이터를 수집할 수 있습니다.

*   **Azure 애플리케이션**: Application Insights를 통해 성능, 예외, 사용자 흐름 등을 모니터링.
*   **Azure 가상 머신 (VM)**: VM Insights (Log Analytics 에이전트)를 통해 OS 성능, 프로세스, 종속성 등을 모니터링.
*   **Azure 컨테이너 (AKS, Container Instances)**: Container Insights를 통해 컨테이너화된 워크로드의 성능 및 로그를 모니터링.
*   **Azure 데이터베이스 (SQL Database, Cosmos DB 등)**: 데이터베이스 성능 메트릭 및 쿼리 로그를 모니터링.
*   **Azure 네트워킹**: Network Watcher, Azure Firewall 로그 등을 통해 네트워크 트래픽 및 보안 이벤트 모니터링.
*   **온프레미스 리소스**: Log Analytics 에이전트를 설치하여 온프레미스 서버의 성능 및 로그를 Azure Monitor로 전송.

이러한 기본 개념들을 이해하는 것은 효과적인 Azure 모니터링 대시보드를 구축하고
운영하는 데 필수적입니다. 다음 단계에서는 Log Analytics와 KQL을 사용하여
로그 데이터를 깊이 있게 분석하는 방법을 학습합니다.
