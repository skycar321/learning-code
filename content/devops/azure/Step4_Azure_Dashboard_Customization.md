# Azure 모니터링 대시보드 학습 - 4단계: Azure 대시보드 구성 및 사용자 지정
# 이 파일은 Azure 모니터링 대시보드 학습 계획의 4단계인 'Azure 대시보드 구성 및 사용자 지정'을 위한
# 개념적인 가이드입니다. Azure Portal에서 대시보드를 생성하고, 타일을 추가하며, 사용자 지정하고,
# 공유하는 방법을 이해하는 데 중점을 둡니다.

## 개요 (Overview)
Azure 대시보드는 클라우드 리소스의 상태와 성능을 한눈에 파악할 수 있도록 돕는 시각화 도구입니다.
다양한 모니터링 데이터를 통합하여 사용자 지정 가능한 보기(view)를 제공하며, 운영 효율성을 높이는 데
핵심적인 역할을 합니다.

## 학습 내용 (Learning Content)

### 1. 새 대시보드 생성 (Creating New Dashboards)
*   **Azure Portal 진입**: Azure Portal (portal.azure.com)에 로그인합니다.
*   **대시보드 섹션으로 이동**: 포털 상단 검색창에 "대시보드"를 검색하거나 왼쪽 탐색 메뉴에서 "대시보드"를 선택합니다.
*   **새 대시보드 추가**: "새 대시보드 만들기" 또는 "+ 추가" 버튼을 클릭하여 빈 캔버스에서 시작하거나, 기존 템플릿에서 시작할 수 있습니다.
*   **대시보드 이름 지정**: 대시보드의 목적을 명확히 나타내는 이름을 지정합니다 (예: "내 웹 애플리케이션 성능 대시보드").

### 2. 타일 추가 및 사용자 지정 (Adding & Customizing Tiles)
대시보드는 다양한 유형의 "타일"로 구성됩니다. 각 타일은 특정 리소스 또는 데이터 소스의 정보를 표시합니다.

*   **메트릭 차트 타일**:
    *   **추가 방법**: "타일 갤러리"에서 "메트릭 차트"를 찾아 캔버스에 끌어다 놓거나, 특정 리소스의 "메트릭" 블레이드에서 "차트를 대시보드에 고정"을 클릭합니다.
    *   **구성**: 모니터링할 리소스(VM, App Service 등), 메트릭(CPU 사용률, HTTP 요청 수 등), 시간 범위, 집계 방식(평균, 최대 등)을 선택합니다.
    *   **사용자 지정**: 차트 제목, 축 레이블, 색상 등을 변경하여 가독성을 높입니다.

*   **로그 쿼리 타일**:
    *   **추가 방법**: Log Analytics 워크스페이스의 "로그" 블레이드에서 KQL 쿼리를 실행한 후 "대시보드에 고정"을 클릭합니다.
    *   **구성**: KQL 쿼리 자체를 직접 입력하거나 수정할 수 있습니다. 쿼리 결과는 테이블, 차트 등 다양한 형태로 시각화됩니다.
    *   **활용**: 특정 오류 로그 추적, 사용자 지정 이벤트 분석, 성능 지표 집계 등 복잡한 데이터 분석 결과를 시각화합니다.

*   **Application Insights 타일**:
    *   **추가 방법**: Application Insights 리소스의 개요 블레이드에서 "Application Insights 대시보드"를 클릭하거나, 특정 차트(예: 서버 응답 시간, 요청 실패율)에서 "대시보드에 고정"을 클릭합니다.
    *   **구성**: 요청 수, 평균 응답 시간, 실패한 요청, 종속성 성능 등 APM(Application Performance Monitoring) 관련 핵심 지표를 표시합니다.
    *   **활용**: 애플리케이션의 엔드 투 엔드 성능, 가용성, 사용량을 모니터링합니다.

*   **기타 유용한 타일**:
    *   **마크다운 타일**: 텍스트, 이미지, 링크 등을 추가하여 대시보드에 컨텍스트나 설명을 제공합니다. (예: 대시보드 사용 가이드, 팀 연락처 정보)
    *   **리소스 타일**: 특정 Azure 리소스(VM, Storage Account 등)의 개요 정보를 표시합니다.
    *   **Service Health 타일**: Azure 서비스의 현재 상태를 표시하여 인프라 문제 파악에 도움을 줍니다.

### 3. 대시보드 공유 및 접근 제어 (Sharing Dashboards & Access Control)
*   **대시보드 공유**:
    *   대시보드는 기본적으로 개인 대시보드입니다. 다른 사용자와 공유하려면 "공유" 버튼을 클릭하여 "리소스 그룹에 게시"합니다.
    *   공유 시 대시보드를 포함할 리소스 그룹을 선택합니다.
*   **접근 제어 (RBAC)**:
    *   공유된 대시보드는 Azure RBAC (역할 기반 접근 제어)를 통해 관리됩니다.
    *   대시보드가 속한 리소스 그룹에 대한 "Reader" 역할을 가진 사용자는 대시보드를 볼 수 있습니다.
    *   "Contributor" 또는 "Owner" 역할은 대시보드를 수정하거나 삭제할 수 있습니다.
    *   **팁**: 대시보드는 리소스 그룹 안에 Azure 리소스로 존재하므로, 다른 리소스와 마찬가지로 RBAC를 적용할 수 있습니다.

### 4. 템플릿(Templates)을 이용한 대시보드 관리
*   **내보내기/가져오기**:
    *   잘 구성된 대시보드를 JSON 템플릿으로 내보내고 다른 환경이나 구독으로 가져올 수 있습니다.
    *   이는 여러 환경에서 일관된 모니터링 보기를 유지하는 데 유용합니다.
*   **자동화**:
    *   Azure Resource Manager (ARM) 템플릿을 사용하여 대시보드 배포를 자동화할 수 있습니다.
    *   이는 IaC (Infrastructure as Code) 원칙에 따라 모니터링 구성을 관리하는 데 효과적입니다.

## 실습 팁 (Practical Tips)
*   **명확한 목적**: 대시보드를 만들기 전에 어떤 정보를 보고 싶은지, 어떤 결정을 내리는 데 도움이 될 것인지 명확히 정의하세요.
*   **간결함**: 하나의 대시보드에 너무 많은 정보를 담으려 하지 마세요. 역할이나 목적에 따라 여러 개의 대시보드를 만드는 것이 더 효과적일 수 있습니다.
*   **정기적인 검토**: 애플리케이션이나 인프라가 변경됨에 따라 대시보드의 유용성도 변할 수 있습니다. 정기적으로 검토하고 업데이트하세요.
*   **공유 및 피드백**: 팀원들과 대시보드를 공유하고 피드백을 받아 개선하세요.

이 단계를 통해 Azure Portal에서 강력하고 유용한 모니터링 대시보드를 직접 구성하고
활용하는 방법을 학습할 수 있습니다.
