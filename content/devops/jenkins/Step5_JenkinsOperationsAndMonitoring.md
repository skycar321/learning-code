# Jenkins 학습 계획 - 5단계: Jenkins 운영 및 모니터링
# 이 파일은 Jenkins 학습 계획의 5단계인 'Jenkins 운영 및 모니터링'을 위한
# 개념적인 설명입니다. Jenkins 시스템을 안정적으로 운영하고, 빌드 이력을 관리하며,
# 문제 발생 시 효율적으로 해결하는 방법을 이해하는 데 중점을 둡니다.

## 개요 (Overview)
Jenkins는 CI/CD 파이프라인의 핵심이기 때문에 항상 안정적으로 작동하고
최적의 성능을 유지해야 합니다. 이를 위해서는 Jenkins 시스템 자체에 대한
정기적인 운영 및 모니터링, 그리고 효율적인 문제 해결 전략이 필요합니다.

## 학습 목표 (Learning Objectives)
*   Jenkins 빌드 이력 관리 방법 이해
*   Jenkins 백업 및 복원 전략 수립
*   Jenkins 시스템 모니터링 방법 학습
*   Jenkins 문제 해결 및 성능 최적화 기법 습득
*   Jenkins 보안 강화 방안 파악

## 학습 내용 (Learning Content)

### 1. 빌드 이력 관리 (Build History Management)
*   **목표**: 디스크 공간 절약 및 Jenkins UI 성능 유지.
*   **설정**: 각 Job(또는 Pipeline) 설정에서 'Build Discarder' 기능을 활성화합니다.
    -   'Log Rotation'을 통해 보관할 빌드 개수 또는 기간을 지정.
    -   'Discard old builds' 옵션 사용.
*   **모범 사례**: 중요한 빌드(예: 릴리즈 빌드)는 영구적으로 보관하고, 개발 빌드나 임시 빌드는 일정 기간 후 삭제하여 디스크 공간을 효율적으로 관리합니다.
*   **나쁜 예시**: 빌드 이력을 무제한으로 보관하여 디스크 공간 부족 문제를 야기하고 Jenkins 성능을 저하시키는 것.

### 2. Jenkins 백업 및 복원 (Backup & Restore)
*   **목표**: Jenkins 시스템 장애 시 데이터 손실 방지 및 빠른 복구.
*   **백업 대상**:
    -   **JENKINS_HOME 디렉토리**: 모든 설정, Job 데이터, 플러그인, 빌드 이력 포함.
    -   Jenkins Configuration as Code (JCasC)를 사용하여 설정을 코드로 관리하는 것이 이상적.
*   **백업 방법**:
    -   **수동**: `JENKINS_HOME` 디렉토리 전체를 압축하여 백업.
    -   **플러그인**: `ThinBackup` 플러그인 등 백업 플러그인 사용.
    -   **자동화**: Cron Job 등을 이용하여 정기적으로 백업 스크립트 실행.
*   **복원**: 백업된 `JENKINS_HOME` 디렉토리를 복원하고 Jenkins를 재시작.
*   **모범 사례**: 정기적인 자동 백업을 구성하고, 복원 절차를 테스트하여 비상 상황에 대비합니다.
*   **나쁜 예시**: Jenkins 백업 전략이 없거나, 백업된 파일의 유효성을 검증하지 않는 것.

### 3. Jenkins 시스템 모니터링 (Monitoring Jenkins System)
*   **목표**: Jenkins Controller 및 Agent의 상태, 성능, 리소스 사용량을 실시간으로 파악하여 문제 발생 전 예방.
*   **모니터링 대상**:
    -   **CPU, Memory, Disk I/O, Network**: 시스템 리소스 사용량.
    -   **빌드 큐, 실행 중인 빌드 수**: 빌드 부하 및 지연.
    -   **플러그인 상태**: 플러그인 오류 여부.
    -   **에이전트 연결 상태**: 에이전트의 가용성.
*   **모니터링 도구**:
    -   **Jenkins 내부 모니터링**: 'Jenkins 관리' -> '시스템 정보' 및 '로그' 확인.
    -   **외부 모니터링**: Prometheus, Grafana, ELK Stack 등을 연동하여 대시보드 구축 및 알림 설정.
*   **나쁜 예시**: Jenkins 시스템이 과부하되거나 에이전트가 오프라인 상태인데도 아무도 인지하지 못하는 것.

### 4. 문제 해결 및 최적화 (Troubleshooting & Optimization)
*   **문제 해결 단계**:
    1.  **로그 확인**: Jenkins 시스템 로그, Job 빌드 로그, 에이전트 로그 확인.
    2.  **Jenkins UI 확인**: Job의 상태, 에러 메시지, 플러그인 상태.
    3.  **시스템 리소스 확인**: CPU, 메모리, 디스크 공간.
    4.  **네트워크 확인**: Controller와 Agent 간 통신 문제.
    5.  **버전 충돌**: 플러그인, JDK, Maven 등의 버전 호환성 문제.
*   **성능 최적화**:
    -   **분산 빌드**: 에이전트를 사용하여 Controller의 부하 분산.
    -   **빌드 병렬화**: 파이프라인 내 Stage 병렬 실행.
    -   **빌드 캐시**: Gradle, Maven 등의 빌드 도구 캐시 활용.
    -   **자원 할당**: Controller 및 Agent에 충분한 CPU/메모리 할당.
    -   **JVM 튜닝**: Jenkins JVM 설정 최적화.
*   **나쁜 예시**: 빌드 실패 시 무작정 재시도하거나, 로그 분석 없이 감으로 문제 해결을 시도하는 것.

### 5. Jenkins 보안 강화 (Enhancing Jenkins Security)
*   **목표**: Jenkins 시스템 및 빌드 데이터 보호.
*   **보안 설정**:
    -   **사용자 인증 및 권한**: 강력한 비밀번호 정책, 역할 기반 접근 제어(RBAC) 설정.
    -   **자격 증명 관리**: Jenkins Credentials를 사용하여 민감 정보(API 키, 비밀번호) 안전하게 저장.
    -   **CSRF 방지**: Cross-Site Request Forgery 방지 기능 활성화.
    -   **SSL/TLS 적용**: Jenkins UI 및 API 통신 암호화.
    -   **플러그인 업데이트**: 보안 취약점 패치를 위해 플러그인을 항상 최신 상태로 유지.
    -   **네트워크 분리**: Jenkins를 내부망에 배치하거나 방화벽 설정으로 접근 제한.
*   **나쁜 예시**: 기본 관리자 계정을 그대로 사용하거나, 비밀번호를 공유하거나, 모든 사용자에게 관리자 권한을 부여하는 것.

이러한 운영 및 모니터링 지식을 통해 Jenkins CI/CD 시스템을 더욱 견고하고 안전하게 관리할 수 있습니다.
