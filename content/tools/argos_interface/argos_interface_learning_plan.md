# Argos란 무엇이며 어떻게 사용하나요?

🚀 Argos는 분산 시스템 환경에서 **데이터 저장소(Data Store) 간의 일관성을 보장**하고, **복잡한 트랜잭션을 관리**하기 위해 설계된 분산 트랜잭션 솔루션입니다.

간단히 말해, 여러 개의 데이터베이스나 서비스를 한 번의 트랜잭션처럼 묶어서 처리할 때, 중간에 실패하더라도 모든 상태를 이전 상태로 되돌리거나(Rollback), 최종 성공을 보장(Commit)하는 시스템을 구축하는 데 사용됩니다.

Argos는 일반적으로 MSA(Microservice Architecture) 환경에서 Saga 패턴이나 **2PC(Two-Phase Commit)**와 같은 분산 트랜잭션 패턴을 구현하는 데 활용됩니다.

## 1. Argos의 주요 역할

Argos는 다음과 같은 복잡한 비즈니스 시나리오에서 핵심적인 역할을 합니다.

| 역할              | 설명                                                                                                                              | 예시 시나리오                                                                                                   |
| :---------------- | :-------------------------------------------------------------------------------------------------------------------------------- | :-------------------------------------------------------------------------------------------------------------- |
| **일관성 보장**   | 여러 마이크로서비스에 걸쳐 데이터가 변경될 때, 최종적으로 모든 데이터가 정합성(Consistency)을 갖도록 보장합니다.                         | 온라인 쇼핑몰에서 주문, 재고 차감, 결제 서비스를 모두 성공시켜야 합니다.                                      |
| **장애 격리 및 복구** | 트랜잭션의 일부 서비스에서 장애가 발생하더라도, 전체 시스템이 멈추지 않고 영향을 받은 서비스만 격리하여 롤백(보상 트랜잭션)을 실행합니다. | 결제는 성공했는데, 재고 차감 서비스가 다운된 경우, 결제를 취소(보상)합니다.                                   |
| **트랜잭션 관리** | 복잡한 비즈니스 로직을 여러 단계(Step)로 나누어 관리하고, 각 단계의 성공 및 실패 여부를 추적합니다.                                   | Saga 패턴의 각 단계(Step)별 상태를 중앙 집중식으로 기록합니다.                                               |

## 2. Argos의 작동 원리 (Saga 패턴 기반)

Argos가 주로 구현하는 Saga 패턴은 하나의 큰 트랜잭션을 여러 개의 **로컬 트랜잭션(Local Transaction)**과 **보상 트랜잭션(Compensation Transaction)**의 시퀀스로 분리하여 실행합니다. Argos는 이 Saga 흐름을 관리하는 오케스트레이터(Orchestrator) 역할을 수행합니다.

1.  **시작 (Start)**: 클라이언트 요청이 Argos의 트랜잭션 코디네이터에 전달됩니다.
2.  **순차 실행 (Execution)**: 코디네이터는 미리 정의된 순서에 따라 마이크로서비스 1, 2, 3에게 로컬 트랜잭션을 실행하도록 명령합니다.
3.  **성공 (Success)**: 모든 서비스가 성공적으로 응답하면, Argos는 최종적으로 트랜잭션이 **완료(Commit)**되었다고 기록합니다.
4.  **실패 및 보상 (Failure & Compensation)**:
    *   만약 서비스 2에서 실패가 발생하면, Argos는 즉시 실행을 멈춥니다.
    *   Argos는 이미 성공한 서비스 1에 대해 로컬 트랜잭션을 취소하는 보상 트랜잭션을 실행하도록 명령합니다. (예: 결제 성공 → 결제 취소)
    *   최종적으로 모든 서비스의 상태가 처음으로 돌아가 전체 롤백을 달성합니다.

## 3. Argos 사용 방법 (개발자 관점)

Argos를 실제 프로젝트에서 사용하려면 일반적으로 다음과 같은 단계를 따릅니다.

1.  **Argos 클라이언트 연동 및 정의**
    *   Argos를 사용하려는 서비스(MSA)에 Argos 클라이언트 라이브러리를 의존성으로 추가합니다.
    *   Saga 정의: 비즈니스 로직에 따라 어떤 마이크로서비스들을 어떤 순서로 호출할지, 그리고 각 서비스의 **보상 트랜잭션(취소 로직)**은 무엇인지를 XML, YAML 또는 코드를 통해 Argos에 정의합니다.

2.  **로컬 트랜잭션 구현**
    *   각 마이크로서비스(예: 주문, 재고, 결제)는 자신의 로컬 데이터베이스에만 커밋하는 간단한 트랜잭션 로직을 구현합니다.
    *   이때, 각 서비스는 자신이 성공했는지, 실패했는지의 결과를 Argos에 다시 보고해야 합니다.

3.  **보상 트랜잭션 구현 (가장 중요)**
    *   각 서비스는 자신의 로컬 트랜잭션을 취소할 수 있는 보상 API를 반드시 구현해야 합니다.
    *   예: `OrderService.createOrder()` (로컬 트랜잭션) ↔ `OrderService.cancelOrder()` (보상 트랜잭션)
    *   Argos는 중앙 코디네이터로서 이 보상 API를 호출하여 실패 시 롤백을 수행합니다.

4.  **실행**
    *   클라이언트가 Argos의 시작 API를 호출하여 Saga 트랜잭션을 시작합니다.
    *   Argos는 정의된 Saga 흐름에 따라 각 마이크로서비스를 호출하고, 트랜잭션의 성공/실패 여부를 조정합니다.

## 4. Spring Boot 애플리케이션에 Argos 통합 예제 (가상)

이 섹션에서는 Spring Boot 애플리케이션에서 Argos와의 연동을 위한 기본적인 코드 구조를 살펴봅니다. Argos가 제공하는 클라이언트 라이브러리를 사용하여 Saga 트랜잭션을 시작하고 관리하는 방식을 가상으로 구현합니다.

**실습 목표**:

*   **Argos 클라이언트 라이브러리 의존성 추가**: `pom.xml`에 Argos 클라이언트 라이브러리(가상) 추가.
*   **Argos 트랜잭션 시작 서비스**: `ArgosService` 내에서 Argos 클라이언트를 통해 분산 트랜잭션을 시작하는 로직 구현.
*   **참가 마이크로서비스의 로컬 트랜잭션 및 보상 트랜잭션**: 각 마이크로서비스 (Order, Inventory, Payment 등)에 대한 가상의 로컬 및 보상 트랜잭션 API 구현.
*   **분산 트랜잭션 상태 모니터링**: Argos가 제공하는 대시보드나 API를 통해 분산 트랜잭션의 상태를 추적.
